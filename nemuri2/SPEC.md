# nemuri II — the lucid hour (sequel spec)

The sequel to **nemuri** (`src/original-nemuri.html`, build 1.19.0): a procedural, first-person,
low-res dream toy in three.js r128. You fall asleep in your bedroom, drift through ~900 dreams
(10 warps = one night), wake to a mood graph, and sleep again. Nights persist and grow darker.

**nemuri II's premise:** in the first game the dream dreamed *on its own*, and you only drifted.
Now you have learned to **notice that you are dreaming**, and the dream has noticed you back.
You can become *lucid*: do reality checks, gain powers, keep a journal, follow the trail of
**the other sleeper** (someone who dreamed here before you and left letters scattered as glowing
memory shards), light **seven lanterns** in the Threshold, and reach **the lucid hour** (the ending).
Nightmares hunt you now, and you carry a lantern against the dark.

Tone: quiet, melancholy, tender, sometimes eerie. Lowercase text everywhere. Short poetic lines.
Never jokey. Never gory. Everything is **original**: do not reference, copy or imitate characters,
places, names or imagery from any existing game (including the one the original credits as inspiration).

## Architecture (read this first)

```
nemuri2/
  src/original-nemuri.html   the untouched original (reference: read it, never edit)
  src/base.html              original + N2 hook bus + debug bridge (generated by tools/make-base.js — do not edit)
  modules/NN-name.js         sequel modules — THE ONLY FILES YOU WRITE (each agent owns exactly one)
  tools/build.js             assembles dist/nemuri-ii.html (+ dist/nemuri-ii.test.html with three inlined)
  tools/smoke.js             headless Chromium smoke test
```

* `node tools/build.js` concatenates `modules/*.js` (sorted by filename) into the game's single
  closure, **after all original content and before `init()`**. Each module is wrapped as
  `try { (function(){ ...your file... })(); } catch(e) {console.error(...)}`.
  Consequences:
  * You can read **and reassign** every engine global directly (`pos`, `yaw`, `pitch`, `phase`,
    `scene`, `camera`, `renderer`, `postMat`, `NEW_RECIPES`, `audio`, `day`, `hintEl` …).
    Function declarations of the engine are mutable bindings: you may wrap one with
    `var _orig = foo; foo = function(){ ...; return _orig.apply(this, arguments); };` — prefer hooks.
  * Your own top-level `var`/`function` are private to your module. Share things only through
    `N2.mods.<yourname> = {...}` and `N2.emit/N2.on` events.
  * `"use strict"` applies. ES5 style like the original (var, function) is preferred; ES2015 is ok.
  * Never write the literal `</script` in a module (build refuses it).
  * The DOM already exists when modules run, but `init()` has NOT run yet: `renderer`, `scene`,
    `camera`, `postMat`, `hintEl`… are still undefined at module-load time. Touch them only inside
    hooks/events (`start`, `frame`, `dreamBuilt`, …) or lazily.
* Test: `node tools/build.js && node tools/smoke.js --worlds=new --keys=KeyJ,Escape --walk=10`
  Options: `--worlds=a,b` | `--worlds=new` (all sequel worlds) | `--worlds=sample:5`,
  `--keys=KeyJ,Escape,...` (pressed after start), `--walk=SECONDS` (wander + press E),
  `--shots=DIR` (screenshots — **look at them** with the Read tool), `--eval="JS expression"`
  (evaluated in the page after start; `__N2` is the debug bridge, see end of `src/base.html`).
  Exit code 1 if any console error / page error occurred. Headless WebGL is software (SwiftShader):
  ~35-45 fps on original worlds — your work must not drop that noticeably.

### Engine facts you need
* Rendering: scene → low-res render target (`internalH = 232`, `makeRT()`) → full-screen post pass
  (`postMat`, `POST_FRAG`, uniforms `uScene uLowRes uTime uWarp uDepth uVig uDesat uBlood uFlash`).
  Materials are **unlit** custom ShaderMaterials from `objMat({color, bright, map, opacity, transparent, side, scroll})`
  with PS1 vertex snapping and distance fog (`U_fog`, `U_fogDist`). There are no three.js lights.
  `THREE.Sprite`/`SpriteMaterial` also work (core's `N2.glowSprite`).
* Player: `pos` (feet), `yaw`, `pitch`, `vy`, `grounded`, `eyeH`, `moveSpeed`, `zoneFlags.flight`,
  `gravMul`, `JUMP_V`; ground via `groundSampler(x,z) -> {y,on}`; collisions `gSolid`; `boundaryR`; `killY`.
* Flow: `phase` ∈ `"title" | "transition" | "play" | "graph"`; `paused`; `inBedroom`; `pullMode`
  (true = the dream may pull you onward through doors/walls/edges). `doWarp(nudge, kind, target)`
  starts a transition; `buildNextDream(firstOfDay, recipeName)` builds; `DAY_LENGTH = 10` warps per night;
  `startGraph()` ends a night (`day++`, saved as localStorage `nemuri_night`).
* Worlds: `NEW_RECIPES[name] = function (P, mood) { ...build with helpers...; return zone; }`
  (`RECIPES === NEW_RECIPES`). See the hand-built waves in the original (search `HAND-BUILT WORLDS`)
  for the zone object format and the helper library (`box cyl sph plane cone rbox slab cbox room
  wallSeg stairsTo doorPortal portalObj objMat pMat bmat jig tex drawWater sAnim tNow rr rrange rint pick pickR SC ...`).
* Text to the player: `beingSpeak(text)` (bottom hint line, used by the original) or `N2.ui.toast(text, sub)`.
* Interactables: `ix(obj, x, z, r, {examine: fn, update: fn, kind})` — E (`examineNearest`) calls `examine`.
* Bedroom: `bedThings.push({x, z, r, kind, prompt})`; E calls `bedroomInteract()` → hook `bedroomInteract`.
* Beings: entries in `entities` (`{obj, update(dt,pos), touch?, kind?}`); horror ones are spawned by
  `populateDream` with `horrorBias`. Survival: `hp`, `maxHp`, `hurtFlash`, `dying`.
* Audio: `audio.ctx`, `audio.master` (GainNode, master volume via `audio.fadeMaster(level, secs)`; normal level 0.28),
  `audio.delay`, `audio.tone(...)`, `audio.noise(...)`, `audio.creature(type, pan, f)`, `audio.gong(freq, pan)`, `N2.chime(freq, dur, vol, type)`.

### The N2 bus (defined in base, extended by `modules/10-core.js`)
Engine hooks (emitted by base). A handler returning `true` **consumes** the event (stops lower-priority handlers and the default action where noted).

| hook | args | when | consumable? |
|---|---|---|---|
| `start` | — | player clicked through the title, first build done | |
| `frame` | dt | every frame, any phase | |
| `play` | dt | every frame while play/transition, not paused, no UI open | |
| `beforeRender` / `afterRender` | — | around the render | |
| `dreamBuilt` | zone, firstOfDay | after a dream (or the bedroom) is built & applied. `zone.archetypeName`, `zone.bedroom`, `zone.palette`, `zone.mood`, `zone.group` | |
| `beforeWarp` | nudge, kind, target | `doWarp` called during play | yes → warp cancelled |
| `warp` | nudge, kind, target | transition out started | |
| `commitTransition` | nudge, target | screen fully white, before next build | |
| `nightEnd` | night, graphPoint | night finished (graph shown) | |
| `keydown` | KeyboardEvent | every key press, before the game | yes → game ignores key |
| `mousedown` | MouseEvent | every mouse press, before the game | yes |
| `examine` | interactable or null | E pressed in a dream | yes → default skipped |
| `bedroomInteract` | bedThing | E pressed on a bedroom thing | yes → default skipped |

`N2.on(name, fn, priority)` (higher priority runs first; core uses 100 for Esc/H), `N2.emit(name, ...)` for your own events.
While `N2.uiOpen > 0` the base ignores keys/mouse and freezes player/world updates.

Core services (`modules/10-core.js`, already written — read it):
`N2.save.get/set/remove/wipeAll` (JSON, prefix `nemuri2_`), `N2.settings` + `N2.setSetting(k,v)` (emits `settings`),
`N2.bind(code,label,owner)` (register your keys for the help screen), `N2.canAct()`,
`N2.ui.css/region/el/toast/panel/open/close/isOpen/toggle/top`, `N2.registerWorld(name, builder, {valence,tags,title,hidden})`,
`N2.prettyName(name)`, `N2.findSpot(minD,maxD[,ox,oz])`, `N2.groundAt(x,z)`, `N2.insideSolid(x,z,y)`,
`N2.glowSprite(color,size)`, `N2.addToDream(obj)` (disposed on next warp), `N2.dreamName()`, `N2.isDreaming()`, `N2.night()`, `N2.chime(...)`.

## Modules & ownership

Each module file is owned by one agent. Read other modules' sections so you integrate, but only
write your own file. Cross-module calls must be **defensive** (`var L = N2.mods.lucid; if (L) L.add(...)`)
because modules may load in any order relative to the feature you need and some may fail.
Expose your public API on `N2.mods.<name>` exactly as listed (you may add more).

### 30-lens.js — ART DIRECTION: a new look for the sequel (top priority of this module)
The user asked: **"It has to have completely different but kinda samey graphics."** nemuri II must be
recognisable at a glance as a *different game* from nemuri 1, while staying in the same family
(low-res, dithered, vertex-snapped, foggy, dreamy, unlit-feeling, monospace UI). Think "the same
dreamer, years later, dreaming in a new medium". The new look is the **default** (`settings.lens`
default = `"lucid"`, change `SETTINGS_DEFAULT.lens` usage accordingly — you may treat a stored value of
`"classic"` from before the first run as unset only if the user never chose it). `classic` remains a
selectable lens that reproduces the original exactly (it is the "nemuri 1 look"; regression-test it).
Required ingredients of the new look (tune until screenshots look gorgeous, side by side with classic):
1. **New world shader.** Materials come from `objMat()` which builds a ShaderMaterial from the globals
   `OBJECT_VERT` / `OBJECT_FRAG` at material-creation time (during dream builds, after modules load), so at
   module load you can reassign `OBJECT_VERT`/`OBJECT_FRAG` and wrap `objMat` to add uniforms
   (`uStyle` shared uniform object: 0 = classic exact original math, 1 = sequel) and
   `extensions: { derivatives: true }`. Sequel shading: faceted "moonlight" — a per-pixel face normal from
   `dFdx/dFdy` of the view-space position, lit by one soft directional key light + hemispheric ambient
   (sky tint from above, ground/fog tint from below) so geometry finally has form and depth; a subtle
   rim/fresnel glow on silhouettes in the dream's glow colour; **height mist** (fog thicker near the
   ground, clearer above); distance hue-shift toward the sky colour (aerial perspective). Keep PS1 vertex
   snapping (perhaps a slightly finer grid) and affine texture wobble so it is still "samey". Emissive
   things (`uBright` > ~1.3) should stay flat/glowing (no shading) and feed bloom.
   Also handle non-objMat materials gracefully (some code uses other THREE materials — leave them).
2. **New default post look ("lucid" lens):** a somewhat higher internal resolution than the original 232
   lines (e.g. ~288-320; respect the resScale setting), soft bloom, a gentle **ink outline** from colour /
   luminance edge detection in the post pass, a **curated palette ramp** colour quantisation (map luminance
   through a per-dream 4-6 colour gradient derived from `zone.palette` / fog / sky — painterly, like a limited
   print) instead of the original's uniform posterize, a different dither (blue-noise-like interleaved
   gradient noise instead of Bayer 8x8), film grain, breathing vignette.
3. **Sky:** the original uses a flat clear colour. In the sequel lens add a gradient sky (zenith → horizon
   glow, faint large stars/aurora bands when the sky is dark) — e.g. a big inverted sphere added to each
   dream on `dreamBuilt` with its own shader (depthWrite false, renderOrder first), or done in post where
   depth is far (no depth texture is available by default — a sky dome is simpler). Remove it in classic.
4. Other lenses (`vhs`, `ink`, `dusk`) build on the sequel world shader too, each with its own grade.
5. Deliver side-by-side screenshots (classic vs lucid) of at least 4 different worlds + the bedroom, READ
   them, and iterate until lucid is clearly a new, more beautiful look that still feels like nemuri.
   Performance: SwiftShader fps must stay within ~20% of classic.

### 40-lucid.js — lucidity & powers (`N2.mods.lucid`)
* Lucidity 0..1 per dream session. HUD meter in `tl` (thin bar + a word: `asleep / stirring / aware / lucid / awake within`).
* **Gain:** reality check success (R), examining things (`examine` hook), finding shards (`shard` event),
  noticing anomalies (emergent events — `emergent` global becomes non-null), time spent calmly.
  **Lose:** horror beings nearby (`entities` with horror kinds — inspect `populateDream`/HORROR section),
  chases, being hurt (`hp` drop), falling out of the world. Slowly settles toward a night-based floor.
* **Reality check (R):** a 2D canvas overlay of your **hands** rising into view (draw them procedurally
  — simple stylized hands); in a dream the fingers are subtly wrong (count shifts, they bend/blur) →
  success, lucidity up, `realityCheck` event; in the bedroom the hands are normal ("you are awake").
  Cooldown. This is the signature mechanic — make it feel great.
* **Powers** unlocked permanently by lifetime lucid moments / nights (persist in `lucid` save); toast +
  `N2.mods.title.flash` on unlock; each costs lucidity:
  * `glide` (hold Space while falling: slow fall), `blink` (Q: dash ~6 m forward, collision-safe,
    with a white smear), `flight` (G: toggles `zoneFlags.flight`-style free flight, drains lucidity,
    ends when it runs out), `stillness` (T: freeze beings + mute, 6 s — reuse `freezeBeings`),
    `steer` (passive: when lucid, the next warp from a touched object/door leans toward the dream
    valence you looked at — set `moodBias`), `recall` (lets the journal re-enter a remembered dream; journal checks `has('recall')`).
* When lucid is high, the dream should look/sound subtly more vivid (emit `lucidity`; lens reacts).
* API: `level()`, `add(amount, reason)`, `has(powerId)`, `powers()` → [{id,title,unlocked,desc,key}], `isLucid()` (level ≥ 0.6).

* **Shards:** in each dream (not bedroom), ~55% chance one shard spawns 14-40 m from spawn on

  a vast round hall over still water at night, seven tall empty lantern posts in a ring, seven doors

  and rarely (5%) as a random warp destination once 7+ shards are found.
* **Lanterns:** every 7 shards = one chapter complete = one lantern can be lit in the Threshold (walk to

### 90-nightmare.js — nightmares, chases, the lantern (`N2.mods.nightmare`)
* **Lantern (F):** you carry a small paper lantern (visible in the lower right of view: a camera-attached
  mesh, swaying with walk bob). When lit: pushes fog back (`U_fogDist` near/far ×1.5-2 around you —
  restore on off/warp), warms the post colour slightly, horror beings nearby hesitate (scale their
