# Visceral: Combat & Animation Overhaul

A Fabric mod for **Minecraft Java Edition 1.21.11** (Fabric Loader **0.19.2**) that replaces
vanilla combat and character animation with a third-person, physically reactive system modelled
on open-world action games:

- an over-the-shoulder camera with free orbit, lock-on framing and collision avoidance
- momentum-based movement: walk, jog and **hold Left Shift to sprint**, with acceleration, leaning,
  turn-in-place and strafing
- timed, weapon-specific melee: slashes, thrusts, overheads, hooks, uppercuts, running attacks
  and finishers, with real wind-up, active and recovery phases
- **E** lock-on, **Q** context-sensitive kick or stomp, **left click** attacks that depend on
  context (weapon, combo step, movement direction, sprinting, target state)
- server-authoritative balance: stagger, stumble, knockdown, wall slams, struggling, crawling,
  failed get-up attempts and recovery
- client-side **active ragdolls**: rigid-body physics with joint limits and muscle motors that
  brace, protect the head, writhe and push back up, blended back into authored get-up animation
- localized, persistent, multiplayer-synced wounds, directional blood particles, ground and wall
  decals, bleeding, and optional dismemberment

Everything is configurable, and visual features can be scaled down or turned off per client.

## Installation

Requirements:

| Component    | Version                        |
|--------------|--------------------------------|
| Minecraft    | Java Edition 1.21.11           |
| Fabric Loader| 0.19.2 or newer                |
| Fabric API   | 0.141.0+1.21.11 or newer       |
| Java         | 21 or newer                    |

1. Install Fabric Loader 0.19.2 for Minecraft 1.21.11 with the
   [Fabric installer](https://fabricmc.net/use/installer/).
2. Download [Fabric API](https://modrinth.com/mod/fabric-api) for 1.21.11 and put it in your
   `.minecraft/mods` folder.
3. Put `visceral-1.0.0.jar` (from `build/libs/` after building, see below) in the same `mods`
   folder.
4. Launch the "fabric-loader-1.21.11" profile.

On first launch the mod applies its control preset (see [Controls](#controls)) and shows a toast
saying so. To keep your own bindings, set `applyControlPreset` to `false` in
`config/visceral-client.json` before launching, or rebind afterwards in *Options → Controls*.

**Servers:** install the same jar and Fabric API on the server. Every player who joins needs the
mod too, because it registers particles, sounds and synced data that Fabric's registry sync
checks on join. In singleplayer the integrated server runs the gameplay side, so nothing else is
needed.

## Building from source

```sh
./gradlew build
```

The jar is written to `build/libs/visceral-1.0.0.jar` (`-sources.jar` alongside). The build uses
Fabric Loom 1.17 with Mojang's official mappings and needs JDK 21. The Gradle wrapper downloads
Gradle itself.

Other useful tasks:

| Task                   | Purpose                                                      |
|------------------------|--------------------------------------------------------------|
| `./gradlew runClient`  | Start a development client with the mod loaded               |
| `./gradlew runServer`  | Start a development dedicated server                         |
| `./gradlew genSources` | Decompile Minecraft for IDE navigation                       |

For automated visual checks, the development client can run a scripted scenario: set
`VISCERAL_AUTOTEST` to a script file and start `./gradlew runClient`. The client creates a
superflat test world and runs the script, one step per line (`cmd /summon ...`, `attack`,
`kick`, `lockon`, `hold forward 20`, `wait 10`, `shot name`, `quit`; see
`client/dev/AutoTest.java`), and saves screenshots to `run/screenshots`. Without the variable
the class does nothing.

The assets under `src/main/resources/assets/visceral` are generated by the Python 3 scripts in
`tools/`; the generated files are committed, so you do not need Python to build:

- `tools/gen_textures.py` draws the particle, decal, wound and reticle textures and the icon.
- `tools/gen_anims.py` writes the keyframe clips in `visceral_animations/` (see
  [Authoring animations](#authoring-animations)).

## Controls

The first-launch preset changes these bindings:

| Action                       | Vanilla       | Visceral preset     |
|------------------------------|---------------|---------------------|
| Sprint (hold)                | Left Ctrl     | **Left Shift**      |
| Sneak                        | Left Shift    | **Left Ctrl**       |
| Inventory                    | E             | **I**               |
| Drop item                    | Q             | **G**               |
| Lock-on / unlock             | –             | **E**               |
| Kick / stomp                 | –             | **Q**               |
| Swap camera shoulder         | –             | **V**               |
| Visceral settings screen     | –             | **O**               |
| Attack                       | Left click    | Left click (timed)  |

All of these appear in *Options → Controls → Key Binds* under **Visceral Combat**. The
*Restore vanilla controls* button in the Visceral settings screen puts the vanilla keys back and
moves lock-on and kick to R and Z.

Sprinting is a hold, not a toggle: hold Shift to accelerate into a sprint, release it to slow
back to a jog. Vanilla's "Sprint: Toggle" accessibility option still works if you prefer it.

**F5** still cycles camera modes. The over-the-shoulder camera replaces vanilla's "third person
back" mode, and first person is unchanged.

## How combat works

### Attacks

A left click starts a swing with three phases: a wind-up that can be cancelled, an active window
in which the weapon sweeps an arc, and a recovery. The server sweeps the arc through the world
and damages whatever it crosses first, with line-of-sight checks, so timing, spacing and
direction all matter. Clicking during the second half of a swing buffers the next attack in the
combo.

Which attack plays depends on context:

| Weapon (item tags)                  | Chain                                   | Contextual variants                                                     |
|-------------------------------------|-----------------------------------------|-------------------------------------------------------------------------|
| Fists                               | jab → cross → hook → uppercut           | running haymaker; standing finisher on a staggered, weakened enemy      |
| Swords (`#minecraft:swords`), tools | right slash → left slash → overhead     | strafe left/right picks the slash side, forward on the opener thrusts, running slash, ground and standing finishers |
| Axes (`#minecraft:axes`, `#visceral:heavy_weapons`) | chop → overhead       | running chop, ground and standing finishers                             |
| Mace (`#visceral:blunt_weapons`)    | swing → overhead                        | running swing, ground finisher                                          |
| Trident, spears (`#visceral:polearms`) | thrust → low thrust → sweep          | strafe for a sweeping cut, ground finisher                              |

- Hits on an enemy in an *opening* deal bonus damage (`openingDamageBonus`). An enemy is open
  while it is staggered, for a moment after you interrupt its wind-up, after it whiffs an
  attack, and just after it gets back up. The lock-on reticle turns red while the target is
  staggered or down.
- **Finishers** start automatically when you attack a downed enemy, or a staggered enemy below
  35 % health, and kill outright below `finisherExecuteThreshold` of max health.
- Damage is **regional**: head hits deal more and limb hits less, and each hit leaves a wound on
  the body part it struck.
- Swing speed follows the held item's attack-speed attribute, so Haste, Mining Fatigue and
  modded weapon stats still apply. The vanilla attack-strength meter and sweep attack are replaced
  while the overhaul is on.

### Kick and stomp (Q)

- A **front kick** hits whatever is in front of you, pushes it back and makes it stumble. A kick
  into a raised shield disables the shield.
- A kick lands harder on an enemy that is winding up an attack (it also cancels the attack) or
  already stumbling, and usually knocks it down. Kick, then kick again as it stumbles.
- Kicking while sprinting or airborne does a **running kick**, which knocks an average enemy
  down on its own.
- Kicking a **downed** enemy **stomps** it, which keeps it down longer.

### Lock-on (E)

Lock-on picks the visible target closest to the centre of the view (within 50°), preferring
hostile mobs. While locked, the camera keeps you on one side of the screen and the target on the
other, your character faces the target and strafes around it, and attacks track it. Flick the mouse sideways to switch to the next target in that direction. Lock-on is
released when you press E again, the target dies, or line of sight is lost for a short time.

### Balance and physical reactions

Every hit transfers a force that depends on the attack, the weapon and the hit direction, and a
mob's or player's balance absorbs it. Heavy entities (`#visceral:heavy`) resist more, and
`#visceral:unshakeable` entities (bosses, golems) are never staggered.

- **Stagger:** small imbalances make the target flinch, larger ones make it stumble back several
  steps. A staggered target cannot attack.
- **Knockdown:** above `knockdownThreshold` the target falls. Clients turn it into an active
  ragdoll while the server lowers its hitbox and pins it in place. A target thrown into a wall
  is slammed and takes `wallSlamDamage`.
- **Downed:** the target lies, struggles and tries to get up. It can fail and fall back, and an
  injured mob that can crawl (`#visceral:can_crawl`) may crawl away first. Get-up animations
  start from the pose the ragdoll ended in, face down or face up.
- **Mobs** telegraph their melee attacks with a short wind-up (`mobWindupTicks`), which gives you
  a window to kick or hit them out of it.

Players are affected too (`knockdownsAffectPlayers`), and recover faster than mobs.

### Wounds and blood

- Each hit leaves a cut, stab or bruise decal at the spot it struck, stored on the entity, saved
  with it and synced to everyone watching.
- Blood sprays in the direction of the hit, and the drops leave splats on blocks. Bleeding
  wounds drip and can deal `bleedDamage` over time.
- Badly hurt legs slow an entity down and badly hurt arms weaken its attacks (`woundEffects`).
- At gore level 2, a lethal heavy hit can sever a limb or the head. The stump shows a wound and
  the severed part becomes its own ragdoll piece.
- Blood colour comes from entity tags: red by default, plus dark, green, purple, bone chips
  (skeletons) or none.

## Multiplayer

- The server is authoritative for damage, hit detection, balance, knockdown state, wounds and
  hitboxes. Each client predicts its own swing animation and sends the server an attack request
  with the attack id, combo step and target hint. The server validates the attack against the
  held weapon, combo timing and cooldowns, then runs the sweep itself with the player's
  server-side aim.
- Clients receive compact packets: physical-state changes, impacts (direction, force, region and
  flags), animation triggers such as mob wind-ups, and server settings. Wounds use a synced data
  attachment, so they load with the entity and persist with it.
- Ragdolls are simulated on each client and stay tethered to the server position, so a downed
  mob is in the same place for everyone. Its limbs may settle slightly differently on each
  screen, but that is cosmetic.
- Gore level and gameplay settings are capped by the server.

## Compatibility

- **Rendering:** the mod hooks into the vanilla 1.21.11 entity render pipeline (render state
  data and `HumanoidModel` part transforms) and draws blood decals with a standard translucent
  entity render type. It has only been tested with the vanilla renderer. Sodium does not replace
  entity rendering, so it should work, but this is untested; with Iris shader packs, decals may
  look different.
- **Models:** full animation and limb ragdolls apply to entities whose model is a
  `HumanoidModel`: players, zombies, husks, drowned, zombie villagers, skeletons, strays,
  wither skeletons, bogged, piglins, piglin brutes and zombified piglins. Other mobs (illagers,
  villagers, witches and animals use other model classes) still get balance, stagger and
  knockdown, wounds, blood and a whole-body tumble when knocked down or killed, but no per-limb
  animation. Armor stands and mannequins (`#visceral:no_physics`) are left alone.
- Modded mobs are covered automatically if their model extends `HumanoidModel`.
- **Animation mods** that also drive player model parts (Player Animator, Emotecraft,
  Not Enough Animations, Better Combat) conflict with this mod's player animation. Turn off
  `animatePlayers` here, or the equivalent option there.
- **Camera mods** (Shoulder Surfing Reloaded, Better Third Person) conflict with the shoulder
  camera. Turn off `shoulderCamera`.
- **Combat mods** that replace left-click attacks conflict with `meleeOverhaul`. Turn it off to
  keep the rest of the mod (reactions, ragdolls, wounds, camera).

## Architecture

```
src/main      (common + server)                src/client  (client only)
├─ combat/   Attacks, AttackDef, SwingGeometry ├─ anim/      Rig, AnimPose, PoseApplier,
│            PlayerCombat (server sweeps),     │            Locomotion, EntityAnimator,
│            MobCombat (wind-ups)              │            AnimClip/ClipLibrary/ClipState
├─ physics/  BalanceSystem (state machine),    ├─ physics/   XPBD Ragdoll, Joint, RigidBody,
│            ImpactSystem (force estimation)   │            HumanoidRagdoll (behaviours),
├─ wound/    WoundSystem (inflict, bleed, heal)│            WorldCollider, RagdollManager
├─ entity/   CombatState, EntityTicker         ├─ camera/    ShoulderCamera, CameraControl
├─ net/      Payloads, ServerNet               ├─ input/     CombatInput, LockOn, Movement
├─ state/    PhysState, Wound, BodyRegion      │            Controller, Keybinds, ControlPreset
├─ config/   CommonConfig                      ├─ fx/        BloodFx, BloodParticles,
└─ mixin/    LivingEntity, Player,             │            BloodDecals, WoundLayer
             MeleeAttackGoal                   ├─ render/    RenderHooks, CorpseManager
                                               └─ mixin/     renderer, camera, input hooks
```

**Server side.** `LivingEntityMixin` adds a `CombatState` to every living entity and routes
damage through `ImpactSystem`. That works out a force vector, a body region and a wound for the
hit, from the attack that is in progress (`CombatContext`) or, for projectiles, explosions, falls
and other damage sources, from the damage source. `BalanceSystem` turns the force into a
balance change and runs the state machine *standing → staggered → falling → downed →
crawling/recovering → standing*. While an entity is down it is immobile and gets a low hitbox
(`getDimensions`), and its AI is stopped. `PlayerCombat` checks and plays attack requests,
sweeping the weapon tip along `SwingGeometry` each tick of the active window and hitting
through vanilla `Player.attack`, so enchantments, criticals, durability and statistics still
apply. `MobCombat` adds a wind-up before vanilla `MeleeAttackGoal` attacks.

**Client animation.** Rendering in 1.21.11 goes through extracted render states, so
`RenderHooks` attaches an `AnimPose` to each humanoid render state during extraction.
`EntityAnimator` builds that pose from layers:

1. **Locomotion:** gait driven by distance travelled, so feet do not slide. Stride length and
   cadence are solved from speed. It adds hip sway, counter-twist, lean into acceleration and
   turns, an arm swing that follows the gait, strafing hip yaw, a limp from leg wounds, and
   crouch, jump, fall and landing poses.
2. **Combat stance:** weapon-specific guard poses when locked on or fighting.
3. **Clips:** keyframed attacks, finishers, get-ups and crawls (quaternion keys, with root
   motion and held-item wrist channels), sampled with blend in/out on top of the lower layers.
4. **Reactions:** spring-driven additive flinches from impact direction and region, the stagger
   stumble, and wall bracing.
5. **IK:** two-bone leg IK that puts the feet on the block surfaces under the character and
   lowers the pelvis to match.
6. **Physics:** while a body is ragdolled, bone transforms come from the simulation. When it
   gets up, the animator blends from the ragdoll snapshot into the get-up clip that matches how
   it is lying.

`PoseApplier` composes the pose hierarchically on the vanilla model parts (the torso pivots at
the waist and carries the head and arms), so the body bends at the hips instead of rotating
around the neck the way vanilla does.

**Ragdolls.** `Ragdoll` is an extended position-based dynamics (XPBD) rigid-body solver
(substepped, fixed 60 Hz, interpolated). Its joint constraints have swing/twist limits and
angular motors whose compliance comes from a muscle strength. Collision runs against the actual
block collision shapes, and capsule self-collision keeps limbs from passing through the body.
`HumanoidRagdoll` builds bodies from the entity's live model cube sizes and runs behaviours on
the motors:

- protective fall: arms reach towards the fall direction and the head tucks
- limp: after heavy impacts or death
- writhing and clutching wounds while downed
- push-up attempts as the entity tries to rise
- death throes

**Wounds and blood.** `WoundLayer` draws wound decals as quads on model part faces, using the
same part transforms, so they follow animation and ragdolls. `BloodDecals` keeps splats and
pools on block faces in a ring buffer and draws them in one batch.

## Technical limitations and alternatives

Some features are impossible as stated in vanilla Minecraft, or too costly. These are the
compromises the mod makes and why.

| Goal | Limitation | What the mod does instead |
|---|---|---|
| Euphoria-level active ragdolls | NaturalMotion's Euphoria is proprietary, and a full biomechanical controller (balance, stepping, grasping) is beyond a mod's frame budget. | XPBD rigid bodies with muscle motors and scripted behaviours (bracing, head protection, writhing, push-ups), blended with authored get-up clips. Standing balance (stumbling, recovery steps) is procedural on the animation side, not simulated. |
| Fully physical, synced ragdolls | Simulating every body on the server and streaming its bone transforms would cost a lot of bandwidth and server time. | The server owns the state, position, hitbox and timing. Ragdolls are simulated per client and tethered to the server position, so limb poses can differ slightly between players. |
| Full-body IK | The vanilla `HumanoidModel` has 6 rigid boxes: no elbows, knees, spine or fingers. | Hip-hinged torso, two-bone leg IK applied by bending the whole leg (no visible knee), and foot-plant pelvis drop. The ragdoll uses a 2-segment spine. |
| Weight shift and foot planting on every block | Block collision shapes are coarse, and per-frame raycasts for every entity are expensive. | Foot IK for nearby entities only (`animationDistance`), cached collision shapes, and gait driven by distance travelled so feet do not slide. |
| Animating every mob | Many vanilla mobs (spiders, creepers, endermen and others) have bespoke, non-humanoid models. | Full skeleton animation for `HumanoidModel` entities. Everything else gets balance, physics knockback, wounds, blood, and a rigid-body tumble on knockdown and death. |
| Gore and dismemberment | Vanilla models cannot be cut, and vanilla has no gore assets. | A whole limb or the head is hidden and spawned as its own ragdoll piece, with a stump wound. It is off by default (`goreLevel` 1) and the server can cap it. |
| Animation authoring | No motion capture, and the mod has no editor. | Clips are defined in `tools/gen_anims.py` by semantic targets (hand and blade directions); a solver turns them into joint angles and writes plain JSON. A resource pack can replace any clip. |
| Vanilla attack cooldown | The vanilla attack-strength bar would fight with timed swings. | The swing timeline paces attacks, and its duration follows attack speed. Turning off `meleeOverhaul` restores vanilla. |
| Shift sprinting | Vanilla Shift is sneak, and shift-clicking in inventories is hardcoded. | Sprint and sneak keybinds are swapped. Shift-click in inventories keeps working because it reads the physical key, not the sneak binding. |
| Performance | Software or low-end GPUs struggle with many ragdolls. | Caps on active ragdolls, corpses and decals, distance cut-offs, sleeping bodies and an adjustable substep count. With all visual features off, the mod's cost is the server logic alone. |

Known issues:

- Get-up clips assume flat ground; on stairs the character may briefly float or clip before foot
  IK catches up.
- Ragdolls do not collide with other entities (only blocks and their own limbs).
- In very tight spaces (one-block tunnels) the shoulder camera pulls in close and can show the
  inside of the character's head.
- The mod adds no shield-specific animation: shields use the vanilla block pose, though kicks
  and finishers react to them.

## Authoring animations

Clips live in `assets/visceral/visceral_animations/*.json`, and a resource pack can override
any of them. A clip has a length in seconds, blend times, per-bone tracks and optional events:

```json
{
  "length": 0.6, "blend_in": 0.06, "blend_out": 0.12, "loop": false,
  "bones": {
    "right_arm": { "rotation": [ {"t": 0.0, "q": [x, y, z, w]}, ... ], "offset": [ ... ] },
    "body":      { "rotation": [ ... ] }
  },
  "root":       { "position": [ ... ], "rotation": [ ... ], "pivot_hip": true },
  "right_item": { "pitch": [ ... ], "roll": [ ... ] }
}
```

Bone rotations are quaternions in the vanilla model part space (+x is the entity's left, +y is
down, −z is forward). The head and arms are relative to the torso; the torso and legs are
relative to the pelvis.

`tools/gen_anims.py` generates every clip from readable specs. You give each key a hand
position and a blade direction, and `tools/pose_helper.py` solves the arm angles. Run it with
no arguments to regenerate every clip, or with group names to regenerate some of them, for
example `python3 tools/gen_anims.py fists guards`.
